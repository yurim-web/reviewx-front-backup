## 관리자 게시글 작성/수정 흐름 튜토리얼

> 이 문서는 **GA/SA 관리자 게시글 작성/수정 페이지**에서
> `PostFormPageClient`와 `PostEditorField`가 어떻게 동작하는지,
> 그리고 Next.js 서버 컴포넌트와 어떻게 연결되는지를 설명하는 튜토리얼입니다.
>
> 대상 파일:
>
> - `src/app/manager_ga/community/posts/create/page.tsx`
> - (유사하게) `src/app/manager_sa/community/posts/create/page.tsx`
> - `src/components/manager/common/community/posts/form/PostFormPageClient.tsx`
> - `src/components/manager/common/community/posts/form/PostEditorField.tsx`

---

## 1. 페이지 진입: 서버 컴포넌트 → 클라이언트 컴포넌트

### 1-1. GA 관리자 게시글 작성 페이지 (`/manager_ga/community/posts/create`)

**파일**: `src/app/manager_ga/community/posts/create/page.tsx`

```tsx
import type { Metadata } from "next";
import PostFormPageClient from "@/components/manager/common/community/posts/form/PostFormPageClient";

// 서버 컴포넌트: metadata 선언 + 클라이언트 페이지 래핑
export const metadata: Metadata = {
  title: "게시글 작성 | ReviewX 관리자",
};

export default function CreatePostPage() {
  // 서버 컴포넌트에서 클라이언트 전용 페이지를 전달만 수행
  return <PostFormPageClient mode="create" />;
}
```

여기서는 **서버 컴포넌트가 하는 일**이 아주 단순합니다.

- 페이지 `<head>`에 들어갈 메타데이터 정의 (`metadata`)
- 실제 UI/로직은 **클라이언트 컴포넌트**인 `PostFormPageClient`에게 모두 위임
- 작성 모드이므로 `mode="create"`만 넘겨줍니다.

> SA 관리자 작성 페이지도 거의 동일한 패턴으로 `PostFormPageClient`를 감싸게 됩니다.

## 2. 최상위 폼 컴포넌트: `PostFormPageClient`

**파일**: `src/components/manager/common/community/posts/form/PostFormPageClient.tsx`

이 컴포넌트는 **게시글 작성/수정 페이지 전체 레이아웃과 폼 상태를 관리하는 중심**입니다.

### 2-1. Props 구조

```ts
interface PostFormPageClientProps {
  mode: "create" | "edit"; // 작성/수정 모드
  post_id?: string; // 수정 모드에서 사용
  initial_data?: {
    category_type: string;
    category: string;
    target: string;
    title: string;
    body: string;
  };
}
```

- **작성 모드(`create`)**: `initial_data` 없이 빈 상태에서 시작
- **수정 모드(`edit`)**: 서버에서 가져온 게시글 데이터를 `initial_data`로 넘겨주어, 폼이 미리 채워진 상태에서 시작하도록 할 수 있음

### 2-2. 주요 상태

```tsx
const [is_mounted, setIsMounted] = useState(false);
const [is_editor_ready, setIsEditorReady] = useState(false);
const [is_editor_unlocked, setIsEditorUnlocked] = useState(false);
const editor_instance_ref = useRef<any>(null);
const title_input_ref = useRef<HTMLInputElement>(null);

// 폼 필드 상태
const [category_type, setCategoryType] = useState(
  initial_data?.category_type || ""
);
const [category, setCategory] = useState(initial_data?.category || "");
const [target, setTarget] = useState(initial_data?.target || "");
const [title, setTitle] = useState(initial_data?.title || "");
```

- **`is_mounted`**: 브라우저에서만 렌더링해야 하는 Toast UI Editor를 위해, 마운트 여부를 체크하는 플래그
- **`is_editor_ready`**: 실제 Editor 인스턴스가 준비되었는지 여부 (동적 import 완료 여부)
- **`is_editor_unlocked`**: 초기에는 클릭 가드로 막아두었다가, 사용자가 클릭하면 에디터를 활성화하기 위한 상태
- **`editor_instance_ref`**: Toast UI Editor 인스턴스를 담아두는 ref (나중에 `getMarkdown()` 같은 API를 호출할 때 사용 가능)
- **폼 상태들**: 구분, 카테고리, 대상, 제목

### 2-3. 마운트 및 스타일 관련 `useEffect`

- `useEffect(() => setIsMounted(true), [])`
  - 클라이언트에서만 `is_mounted`를 `true`로 만들기 위해 사용
- 에디터 버튼 마진/기본 텍스트 제거를 위한 `<style>` 태그 주입
  - Toast UI Editor의 기본 스타일을 커스터마이징하기 위한 CSS를 `document.head`에 직접 추가/제거
- 모드에 따른 에디터 준비 상태 설정
  - `create` 모드: 초기엔 스켈레톤을 표시하고, 실제 에디터 준비는 `PostEditorField`에서 처리
  - `edit` 모드: 초기부터 `is_editor_ready = true`로 설정 (수정 화면에서는 바로 에디터가 보여야 하기 때문)

### 2-4. 화면 레이아웃 구성

`PostFormPageClient`는 크게 세 영역으로 나뉩니다.

1. **상단 헤더 바** (`header_bar`)
2. **좌측 사이드바 메뉴** (`sidebar`)
3. **우측 메인 컨텐츠 영역** (`main_content`)

메인 컨텐츠 영역 안에 **실제 게시글 폼 카드**가 있고, 그 안에 다음 요소들이 있습니다.

- 구분 드롭다운 (`CustomDropdown` + `category_type`) → "공지사항" / "자주 묻는 질문" 등
- 카테고리 드롭다운 (`category`)
- 대상 드롭다운 (`target`) → 전체/리뷰어/파트너/관리자
- 제목 입력 (`title`) → FAQ일 경우 라벨이 "질문"으로 표시
- 본문 에디터 (`PostEditorField`) → 라벨이 FAQ일 경우 "답변"으로 표시
- 등록/수정 버튼 → 현재는 UI만 있고 실제 저장 로직은 아직 연결되지 않음

> 여기서 **폼 상태(구분/카테고리/대상/제목)**는 `PostFormPageClient`가 직접 관리하고,
> **본문 내용**은 `PostEditorField` + Toast UI Editor가 별도로 관리합니다.

## 3. Toast UI Editor 래퍼: `PostEditorField`

**파일**: `src/components/manager/common/community/posts/form/PostEditorField.tsx`

이 컴포넌트는 **Toast UI Editor를 직접 다루는 역할**을 합니다. (`dynamic import` + 로딩 스켈레톤 + 클릭 가드)

### 3-1. 동적 import로 Editor 불러오기

```tsx
const ToastEditor = dynamic<ToastEditorProps>(
  () =>
    import("@toast-ui/react-editor").then(
      (mod) => mod.Editor as unknown as ComponentType<ToastEditorProps>
    ),
  {
    ssr: false,
    loading: () => <div className={styles.editor_skeleton}>에디터 로딩중…</div>,
  }
);
```

- **`ssr: false`**: 서버 사이드 렌더링 시점에는 Editor를 렌더링하지 않도록 설정
- `loading` 옵션: Editor가 아직 로드되지 않았을 때 보여줄 로딩 UI (스켈레톤)

### 3-2. Props 구조

```ts
interface PostEditorFieldProps {
  is_mounted: boolean;
  is_editor_ready: boolean;
  setIsEditorReady: Dispatch<SetStateAction<boolean>>;
  is_editor_unlocked: boolean;
  setIsEditorUnlocked: Dispatch<SetStateAction<boolean>>;
  mode: "create" | "edit";
  initial_data?: { body: string } | null;
  editor_instance_ref: MutableRefObject<any>;
  title_input_ref: RefObject<HTMLInputElement | null>; // (현재는 사용 X, 확장용)
  body_label: string; // "내용" 또는 "답변" 등 라벨 텍스트
}
```

- 상위 컴포넌트(`PostFormPageClient`)에서 관리하는 상태/함수들을 그대로 받아와서, Editor의 렌더링/잠금 해제 로직에 활용합니다.

### 3-3. 렌더링 로직 요약

```tsx
return (
  <div className={styles.form_field}>
    <label className={styles.input_label} htmlFor="body">
      {body_label}
    </label>
    <div
      className={`${styles.editor_container} ${
        !is_editor_unlocked ? styles.editor_disabled : ""
      }`}
    >
      {is_mounted ? (
        <>
          {/* 실제 Editor 영역 */}
          <div
            style={{
              display: mode === "create" && !is_editor_ready ? "none" : "block",
            }}
          >
            <ToastEditor
              ref={(editor: any) => {
                // 1) ref에 Editor 인스턴스 저장
                // 2) is_editor_ready = true 로 설정
              }}
              initialValue={initial_data?.body ?? "  "}
              initialEditType="wysiwyg"
              previewStyle="vertical"
              height="340px"
              usageStatistics={false}
              placeholder=""
              autofocus={false}
            />
          </div>

          {/* 작성 모드 + 아직 준비 안 되었을 때 스켈레톤 표시 */}
          {mode === "create" && !is_editor_ready && (
            <div className={styles.editor_skeleton}>에디터 로딩중…</div>
          )}

          {/* 에디터가 준비되었지만 아직 잠겨 있을 때 클릭 가드 */}
          {is_editor_ready && !is_editor_unlocked && (
            <div
              className={styles.editor_click_guard}
              onClick={() => setIsEditorUnlocked(true)}
              aria-label="에디터 활성화"
            />
          )}
        </>
      ) : (
        <div className={styles.editor_skeleton}>에디터 로딩중…</div>
      )}
    </div>
  </div>
);
```

### 3-4. Editor 인스턴스 참조 저장

```tsx
ref={(editor: any) => {
  if (!editor) return;
  try {
    if (editor.getInstance) {
      editor_instance_ref.current = editor.getInstance();
    } else if (editor.getRootElement) {
      const rootElement = editor.getRootElement();
      if (rootElement) {
        editor_instance_ref.current = (rootElement as any).__editor__;
      }
    }
  } catch (e) {
    // ignore
  }
  setIsEditorReady(true);
}}
```

- Toast UI Editor의 경우, `ref`를 통해 실제 Editor 객체에 접근할 수 있는데,
  라이브러리 버전/구조에 따라 `getInstance()` 또는 내부 `__editor__`를 써야 할 수 있습니다.
- 이 코드에서는 두 가지 경우를 모두 처리해서 **`editor_instance_ref.current`에 실제 Editor 인스턴스를 저장**합니다.
- 인스턴스 확보가 끝나면 `setIsEditorReady(true)`를 호출하여, 상위 컴포넌트가 "에디터 준비 완료" 상태를 알 수 있도록 합니다.

### 3-5. 잠금(Click Guard)과 스켈레톤의 의미

- **스켈레톤 (`editor_skeleton`)**
  - 에디터가 로딩 중일 때 사용자에게 "지금 준비 중입니다"를 시각적으로 알려주는 영역
- **클릭 가드 (`editor_click_guard`)**
  - 에디터가 이미 준비는 되었지만, 사용자가 한 번 클릭하기 전까지는 입력을 막고 싶은 경우 사용
  - `is_editor_ready && !is_editor_unlocked` 조건에서만 렌더링
  - 사용자가 가드를 클릭하면 `setIsEditorUnlocked(true)`가 호출되어 입력이 가능해짐

> 이 구조 덕분에, **초기 로딩/포커스/입력 가능 상태**를 세밀하게 제어할 수 있습니다.

## 4. 전체 데이터/이벤트 흐름 정리

1. 브라우저가 `/manager_ga/community/posts/create`로 진입
2. 서버 컴포넌트 `CreatePostPage`가 렌더링되면서 `PostFormPageClient mode="create"`를 반환
3. 클라이언트에서 `PostFormPageClient`가 마운트되며:
   - `is_mounted = true`
   - 드롭다운/제목 입력 상태 초기화
   - `PostEditorField`에 필요한 상태/함수를 props로 전달
4. `PostEditorField`가 마운트되면:
   - `dynamic` import를 통해 Toast UI Editor를 로드
   - 로딩 중에는 스켈레톤 표시
   - Editor 인스턴스가 생성되면 `editor_instance_ref.current`에 저장 + `setIsEditorReady(true)` 호출
5. 사용자가 Editor 영역을 클릭하면:
   - 클릭 가드가 `setIsEditorUnlocked(true)`를 호출
   - `editor_disabled` 클래스가 제거되어 에디터 편집 가능
6. (추후 구현 예정) 저장 버튼 클릭 시:
   - `category_type`, `category`, `target`, `title`은 `useState` 값에서 가져오고
   - 본문 내용은 `editor_instance_ref.current.getMarkdown()` 또는 `getHTML()`로 읽어서 API로 전송하는 형태로 확장할 수 있습니다.

## 5. 이 컴포넌트를 이해하는 데 도움이 되는 연습

1. `PostFormPageClient`에서 **폼 필드를 하나 더 추가**해 보기 (예: "노출 여부" 토글)
   - `useState`로 상태 추가 → `CustomDropdown`이나 체크박스로 UI 추가
2. `PostEditorField`에서 **에디터 높이**를 조정해 보기 (`height="340px" → "500px"`)
3. (조금 더 진도 나갔을 때) 저장 버튼에 `onClick`을 달고,
   - `console.log({ category_type, category, target, title, body: editor_instance_ref.current?.getMarkdown() })`를 찍어보면서 실제 값이 어떻게 나오는지 확인해 보기

이 튜토리얼을 한 번 쭉 읽어보면, "**폼의 기본 필드는 상위 컴포넌트에서 관리하고, 복잡한 WYSIWYG 에디터는 별도 컴포넌트+ref로 관리한다**"는 패턴을 이해할 수 있고,
이 패턴을 다른 관리자 페이지(예: 다른 종류의 게시글, 공지사항 등)에도 그대로 확장해서 사용할 수 있습니다.
